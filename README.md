# arch-bench — код и результаты эксперимента (серия 2)

Сравнение монолитной, трёхзвенной, микросервисной и бессерверной реализаций одного веб-приложения
под ступенчатой нагрузкой (10–5000 виртуальных пользователей, k6). Серия 2: 4 архитектуры × 10 прогонов
× 8 ступеней = 320 ступеней, 6–8 октября 2026 г.; все 40 прогонов валидны.

## Код

| Каталог | Содержимое |
|---|---|
| `apps/` | приложение: монолит (`apps/monolith`), шлюз (`apps/gateway`), микросервисы (`apps/services`), общий код домена (`apps/shared`) |
| `serverless/` | функции OpenFaaS (тот же код домена) |
| `database/` | схема, миграции, детерминированный генератор данных (seed 20261004) |
| `infrastructure/` | генерация конфигураций развёртывания; `infrastructure/generated/` — использованные манифесты Docker Compose / Kubernetes / OpenFaaS |
| `experiments/configs/bench.yaml` | все параметры эксперимента (SHA-256 записан в метаданных каждого прогона) |
| `experiments/k6/` | сценарий нагрузки k6 |
| `experiments/orchestrator/`, `experiments/run_experiment.py` | запуск серии, сбор метрик, критерии невалидности прогона |
| `experiments/analysis/` | обработка: метрики, агрегаты, закон Литтла, модель закрытой системы, статистика (Манн–Уитни, Холм, δ Клиффа, бутстреп) |
| `scripts/` | установка и развёртывание на сервере, проверка результатов (`validate_results.py`), поисковый анализ операций (`exploratory/`), анализ чувствительности окна CPU и реплик (`sensitivity/`) |
| `tests/` | модульные и интеграционные тесты |

## Результаты (`results/series2/`)

| Каталог | Содержимое |
|---|---|
| `analysis/` | `run_level.csv` (320 строк: прогон × ступень), `aggregates.csv` (средние, медианы, 95 % бутстреп-интервалы), таблицы и рисунки основного анализа, `analysis_meta.json` |
| `post_series/` | производные показатели (загрузка и удельный спрос CPU, закон Литтла, закон закрытой системы, точки насыщения, попарные сравнения) |
| `operations/explore_ops.csv` | успешность и длительность по отдельным операциям (поисковый анализ) |
| `sensitivity/` | пересчёт CPU по точному окну k6, смещение окон мониторинга, число готовых реплик |
| `meta/runs/`, `meta/steps/` | метаданные 40 прогонов (окружение, версии, конфигурация, валидность) и ступеней |
| `meta/invalid_reasons.txt` | причины невалидных попыток (перезапущены, не удалены) |
| `meta/series_events.log` | журнал выполнения серии |

Сырые данные (2,1 ГБ, 2440 файлов: ответы k6, мониторинг) в репозиторий не входят из-за объёма.
В метаданных и журнале публичные IP-адреса серверов заменены на `SUT_PUBLIC_IP` и `GENERATOR_PUBLIC_IP`;
другие изменения в файлах результатов не вносились.

## Воспроизведение

```
make venv          # окружение Python 3.12
make test          # тесты
make render        # манифесты развёртывания из bench.yaml
make experiment    # полная серия на сервере (Ubuntu 24.04, Docker, k3s, OpenFaaS)
make analysis      # анализ сырых данных: python -m experiments.analysis.run_analysis
make validate      # проверка полноты и согласованности результатов
```
